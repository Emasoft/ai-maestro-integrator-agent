# Incorporate governance rules R41-R49 and R52 into the INTEGRATOR persona

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative; supersedes the body) — 2026-08-08

- **Not started.** The gap is measured and stamped, not closed.
- **NEXT ACTION:** read `design/specs/governance-spec.md` (blob `b1ffe5998966`) for each of
  R41–R49 and R52, decide per rule whether it BINDS the INTEGRATOR or is a fact-to-know
  about MANAGER/COS powers, and extend the persona's governance section in that existing
  two-list shape. Then re-stamp and widen
  `tests/test_governance_compliance.py::check_persona_has_governance_section`.

## Why

The persona's governance section covers **R26–R40** and cited catalog **v4.0.1**. Measured
2026-08-08 against the live `governance-rules` branch: the spec is **v2.4.3** and the
catalog **v5.3.3** (2026-08-06), and the rule set runs **R1–R52**. So the persona was
roughly 1.3 catalog-major-versions stale and is missing **R41–R49 + R52** outright.

Found while implementing GOV-VAL-06 at CORE's direction — not by an audit aimed at this.
The version citation was a bare `v4.0.1` string that nothing checked, which is exactly the
condition GOV-VER-02 describes: *"a declared version ≠ the live one is a detectable
failure"* — undetectable precisely because nothing ever declared a checkable version.

## What is already done (do not redo)

- The persona now carries a **GOV-VER-02 currency stamp** with both blob shas, a read-date,
  and the polling command inline.
- `check_governance_stamp_matches_live_spec` makes that stamp machine-checkable: it fails
  when a stamped blob differs from live, and fails when the stamp is absent.
- **The stamp deliberately declares PARTIAL conformance and names this TRDD.** Declaring
  `conforms-to-spec: governance@2.4.3` while R41–R52 are absent would assert conformance
  this plugin does not have — re-creating the undetectable drift the stamp exists to end,
  with a green check on top of it. A stamp that overstates is worse than no stamp.

## Scope

| Rule | Key phrase (from the live spec) |
|---|---|
| R41.0 | two-protocols |
| R42.0 | an agent influences another agent's **WORK** |
| R43.0 / R44.0 | invariant |
| R45.1 | team-same-host — a team requires all agents on the same host |
| R46.1 | one-unified-list (left sidebar) |
| R47.1 | user names unique across the entire Tailscale VPN |
| R48.0 / R49.0 / R52.0 | invariant |

Several are plainly UI/topology rules that will land in "facts you must know" rather than
"binds you directly" — but that determination must come from reading each rule, not from
the key phrase. R42 (influencing another agent's work) and R41 (two-protocols) are the
likeliest to bind the INTEGRATOR directly and should be read first.

## Not to be done here

Do **not** bump the stamp's version numbers as part of any other change. The stamp records a
READ that actually happened; advancing it without re-reading converts a diligence record
into a false currency claim, which is the one failure mode this whole mechanism is for.
